# 智能代码判题与教学辅助系统 (CourseJudge) - 需求规格说明书 (SRS)

## 1. 引言

### 1.1 项目背景与建设目标
在高校程序设计与算法类课程教学中，教学核心场景通常围绕“老师建班布置作业 $\to$ 学生编码提交 $\to$ 系统自动判分 $\to$ 教学反馈与补弱”展开。
本项目是一个以 **Python** 作为主开发语言、采用 **PyWebView 独立桌面客户端**形态呈现的**智能代码判题与教学辅助系统 (CourseJudge)**。系统围绕**老师端作业管理与学情洞察**和**学生端编程实践与巩固补弱**两大核心主线，深度结合大语言模型 (LLM) API 赋能，重点实现：
1. **轻量便携、落地即用**：采用 Python + PyWebView 封装为独立原生桌面应用窗口，界面集成 Monaco 代码编辑器与 ECharts 数据大屏。配合**“编译器智能双模自适应探针”**（优先检测系统环境，兜底使用内置便携版编译器）与 **SQLite 项目级单文件数据库**，实现无论在任何新电脑上均能**开箱即用、零环境配置、随拷随走**。
2. **班级教学管理体系**：老师与学生基于班级建立关联，实现作业的精准分发与学生提交记录跟踪。
3. **轻量专注的题目源**：去除冗余杂乱的公共题库，所有题目聚焦于**老师布置的作业/考试题**与**学生专属强化训练题**。
4. **LLM 教学深度赋能**：老师端通过自然语言交互实现快速出题与自动化测试用例闭环验证；学生端在交卷后一键生成短板诊断报告，并支持动态生成专属巩固题目；提供首页 AI 助教答疑对话。
5. **教学反馈闭环大屏**：教师端提供作业维度的“班级整体学情与薄弱知识点数据大屏”，直观暴露教学薄弱环节。

## 2. 系统用户与角色体系

| 角色 | 场景与定位 | 核心权限与职责 |
| :--- | :--- | :--- |
| **教师 (Teacher)** | 教学组织者与发布者 | 创建并管理班级、布置作业（练习/考试模式）、利用 LLM 辅助出题与生成测试用例、查看班级整体学情与薄弱知识点大屏 |
| **学生 (Student)** | 答题练习与补弱者 | 通过邀请码加入班级、在“我的作业”中作答、C++ 在线自测运行与正式提交、考后一键获取 AI 短板诊断、在专属强化题本中针对性复盘、AI 对话问答 |
| **管理员 (Admin)** *(系统内置)* | 基础配置保障 | 负责系统级基础账号维护与全局大模型 API Key 统一配置 |

## 3. 功能性需求规格

### 3.1 班级管理模块
- **教师端**：
  - 创建班级（输入班级名称，系统自动生成 6 位唯一加入邀请码）。
  - 查看本班学生名册、移出误入学生。
- **学生端**：
  - 输入 6 位邀请码申请加入指定班级。
  - 查看已加入的班级列表及授课老师。

---

### 3.2 教师端核心模块：作业管理与智能出题

#### 3.2.1 作业/考试发布与编排
- **作业基础属性**：
  - 作业标题、所属班级、有效起止时间。
  - **模式支持**：
    - **练习模式**：学生提交后实时查看每组测试点的状态（AC/WA/TLE/RE/CE）与得分，允许无限次修改重交。
    - **考试模式**：学生在答题期间仅能使用“自测运行”验证逻辑，**正式交卷仅限 1 次**；答题期间隐藏详细测试点数据，防泄露题意。
- **题目清单编排（逐题录入或智能生成）**：
  - 老师点击“添加题目”，可自由选择：
    1. **手动录入**：填写题面 Markdown、样例、时空限制与测试用例。
    2. **LLM 辅助快速出题（重点）**：
       - 老师输入意图（如：“出1道贪心算法-区间重叠问题，适合大一，中等难度”）。
       - LLM 自动生成规范题面与标准 C++ 解答（AC 代码）。
       - 点击“自动生成测试用例”，LLM 自动分析边界条件输出测试输入，后端调用编译器运行标准解答自动捕获输出，实现测试用例 100% 正确配对。
       - 老师预览确认后，点击“加入作业清单”。
  - 编排完毕后，一键发布至目标班级。

#### 3.2.2 班级学情与薄弱知识点大屏看板（重点）
- **作业概况图表**：班级应交人数、实交人数、平均分、各分数段（优秀/良好/及格/待提高）直方图。
- **题目正答率漏斗**：每道题目的通过率与耗时统计、错误类型占比饼图。
- **班级薄弱知识点 Top 诊断**：
  - 自动汇总全班学生失分最多的知识点（如：“本班 64% 的同学在【动态规划-状态转移】出现失分”），辅助教师针对性备课。

---

### 3.3 学生端核心模块：做题、判分与强化训练

#### 3.3.1 “我的作业”大厅
- 按照所属班级清晰罗列待完成、进行中、已截止的作业/考试列表，标注模式（练习/考试）与倒计时。

#### 3.3.2 现代化编程工作台与判题交互
- **编辑器体验**：集成 Monaco Editor（VS Code 核心），提供原汁原味的 C++ 代码语法高亮、自动括号补全与缩进辅助。
- **本地自测运行（不计分）**：
  - 学生可在界面输入自定义测试数据，点击“自测运行”，系统仅在本地沙箱编译运行并返回输出与耗时，供交卷前逻辑排错。
- **正式提交判题**：
  - **练习模式**：提交后逐点反馈通过结果。
  - **考试模式**：提交前二次警示确认，提交后锁定该题，记录最终单次成绩。

#### 3.3.3 考后 LLM 短板一键分析
- 作业/考试结束后，学生点击“AI 短板诊断”。
- 系统收集学生未拿满分的题目与提交源码，调用大模型 API 深度剖析：
  1. **代码诊断**：指出逻辑盲区或未考虑的边界条件。
  2. **短板提炼**：清晰提炼出薄弱知识点标签（如“动态规划-状态压缩”）。
  3. **解题思路指导**：给出最优解法与算法核心指导。

#### 3.3.4 专属强化训练题本
- **一键生成强化题**：在短板诊断下方，点击“针对此短板生成专项训练题”，LLM 即时生成 1 道阶梯巩固题并配套测试用例。
- **历史训练题本**：独立的复习归档区，永久保存学生所有专属强化题目，学生可随时重写代码、提交判题，实现查漏补缺的真正闭环。

---

### 3.4 首页 AI 助手问答模块
- 全局常驻的 AI 助手对话窗口，支持流式打字输出，供师生咨询 C++ 语法问题、编译报错含义分析、算法概念与调试思路。

---

## 4. 非功能性需求与运行环境规格

1. **客户端与窗口形态**：
   - 采用 PyWebView 封装为单应用独立 Windows 桌面窗口，启动无需配置 Web 服务器或外部浏览器。
2. **编译器与评测可靠性 (智能双模探针)**：
   - 系统自动探测环境，优先使用系统已有的 `g++`；若未安装，平滑降级使用项目内置约 40~50MB 的绿色便携式编译器，实现“零外部环境依赖，落地即用”。
   - 子进程必须严格配置超时时间（默认 1000ms），彻底杜绝死循环挂死系统。
3. **数据安全性与极简设计**：
   - 使用项目级 SQLite 数据库（`course_judge.db`），无需配置外部数据库服务器，随拷随走。
   - 账号信息严格遵循极简原则，仅包含学工号、姓名、密码与角色，不收集手机、邮箱等无关隐私字段。
   - 密码直接明文存储，方便课设阶段直观调试与测试验证。
   - 考试模式严格实行服务端权限鉴权，防提前偷看隐藏用例。
