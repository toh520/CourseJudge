### Phase 1: 核心配置、极简持久层与数据模型 【待开发】⏳

> **目标**：搭建稳固的底层基础设施，实现零硬编码的配置动态读取，完成 SQLite 单文件数据库引擎与全套 ORM 数据实体映射。

- [ ] **Step 1.1: 基础设施配置读取模块 (`app/core/config.py`)**
  - **核心任务**：基于 `pydantic-settings` 读取本地 `.env` 文件，提供强类型配置单例 `settings`（包含 `DATABASE_URL`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_NAME`、超时限制等）。
  - **规范要求**：代码中严禁任何硬编码字符串，添加标准中文注释。
- [ ] **Step 1.2: SQLite 数据库引擎与会话工厂 (`app/core/database.py`)**
  - **核心任务**：初始化 SQLAlchemy 2.0 异步/同步引擎，配置 `sessionmaker`，编写数据库依赖注入生成器 `get_db()`，提供自动建表函数 `init_db()`。
- [ ] **Step 1.3: 极简数据库实体 ORM 建模 (`app/models/`)**
  - **核心任务**：严格遵照“极致克制原则”创建数据表模型，各文件职责单一：
    - `models/user.py`：用户实体（`id`, `username`, `real_name`, `password` 明文, `role`, `created_at`）；
    - `models/clazz.py`：班级实体（`id`, `name`, `invite_code`, `teacher_id`）与班级成员实体；
    - `models/assignment.py`：作业/考试实体（`id`, `class_id`, `title`, `type`, `start_time`, `end_time`）；
    - `models/problem.py`：题目实体与测试用例实体（`test_cases`）；
    - `models/submission.py`：学生提交记录实体（`status`, `score`, `code`, `time_used_ms`, `compiler_output`）；
    - `models/training.py`：专属强化训练题实体（`student_id`, `knowledge_tag`, `test_cases_json`）；
    - `models/chat.py`：AI 问答消息历史记录实体。
- [ ] **Step 1.4: 轻量身份鉴权工具 (`app/core/security.py`)**
  - **核心任务**：明文密码核对、JWT Token 签名与有效性验证、当前登录用户依赖解析。
- [ ] **Step 1.5: 阶段验收与自动化测试**
  - **验收测试**：编写轻量验证脚本 `tests/test_database.py`，测试配置加载、数据库自动建表、增删改查链路 100% 通过。

### Phase 2: C++ 判题引擎与编译器智能双模探针 【待开发】⏳

> **目标**：打造可靠、防死循环、自适应环境的 C++ 编译与受限评测核心子系统。

- [ ] **Step 2.1: 编译器智能双模自适应探针 (`app/services/judge/compiler_probe.py`)**
  - **核心任务**：探测本机系统 `PATH` 中的 `g++`；若未配置，平滑降级探测项目内置便携路径（`project/compiler/bin/g++.exe`）；提供状态查询接口。
- [ ] **Step 2.2: 受限子进程执行沙箱 (`app/services/judge/sandbox_runner.py`)**
  - **核心任务**：封装 `subprocess` 调用；在独立隔离目录（`storage/temp_judge/{uuid}/`）编译源码；执行可执行文件并重定向 `stdin` 与 `stdout`；设定严格的 CPU 运行超时阈值（强杀进程，返回 TLE）；捕获运行时段错误与除零异常（返回 RE）。
- [ ] **Step 2.3: 智能文本输出比对器 (`app/services/judge/output_comparator.py`)**
  - **核心任务**：比对学生输出与标准答案，自动过滤 Windows/Linux 换行符差异 (`\r\n` vs `\n`)、忽略行末空白与文件末尾多余空行，判定 `AC` 或 `WA`。
- [ ] **Step 2.4: 判题调度与自测运行服务 (`app/services/judge/judge_service.py`)**
  - **核心任务**：
    - `run_custom_test()`：单点自测运行逻辑（不记录分数）；
    - `judge_submission()`：遍历题目全部隐藏评测用例，计算通过百分比与得分。
- [ ] **Step 2.5: 阶段验收与自动化测试**
  - **验收测试**：编写 `tests/test_judge.py`，分别输入正常 AC、逻辑错 WA、死循环超时 TLE、语法错 CE、段错误 RE 的 C++ 代码，验证状态判定与日志捕获 100% 准确。

### Phase 3: 大语言模型 (LLM) 服务与智能闭环 【待开发】⏳

> **目标**：基于 OpenAI 兼容协议接入大模型，实现 AI 辅助出题、测试用例正向闭环验证、考后短板诊断与一键补弱。

- [ ] **Step 3.1: OpenAI 兼容统一客户端封装 (`app/services/llm/client.py`)**
  - **核心任务**：封装 `openai.OpenAI` SDK 调用，统一异常捕获与重试机制，支持普通请求与 SSE 流式输出。
- [ ] **Step 3.2: 教师端智能出题与 Prompt 模块 (`app/services/llm/generator.py` & `prompts/`)**
  - **核心任务**：根据教师输入的自然语言意图，结构化生成 Markdown 题面、时空限制、输入输出样例及标准 C++ 解题代码（AC 源码）。
- [ ] **Step 3.3: 测试用例生成与 100% 正向验证闭环**
  - **核心任务**：调用 LLM 针对题目生成多组包含极限值与边界情况的测试输入数据；在后端**自动调用 Step 2 编译运行标准 AC 代码**，抓取标准输出作为预期结果，确保用例与解答 100% 绝对契合。
- [ ] **Step 3.4: 考后学情短板深度诊断服务 (`app/services/llm/diagnostician.py`)**
  - **核心任务**：提取学生未拿满分题目的提交代码与评测错误点，Prompt 引导模型输出逻辑缺陷分析、学习指导与核心薄弱知识点标签（如“动态规划-状态转移”）。
- [ ] **Step 3.5: 针对薄弱点的一键专属强化题生成**
  - **核心任务**：依据短板标签动态生成 1 道同类知识点巩固题及配套用例，自动落库至学生专属训练题本。
- [ ] **Step 3.6: 首页 AI 智能助教对话服务**
  - **核心任务**：提供多轮代码、语法报错与算法思路问答交互，支持打字机流式输出。
- [ ] **Step 3.7: 阶段验收与自动化测试**
  - **验收测试**：编写 `tests/test_llm.py`，使用真实 `.env` 测试出题 JSON 解析、标准代码运行用例回填闭环与短板诊断输出。

### Phase 4: 业务逻辑服务与 RESTful API 路由 【待开发】⏳

> **目标**：连接数据库与底层服务，实现清晰分层的 FastAPI 接口控制器与 Pydantic 数据校验。

- [ ] **Step 4.1: 系统状态与探针路由 (`app/api/system.py`)**
  - **接口**：`GET /api/v1/system/status`，返回当前编译器探针命中模式与就绪状态。
- [ ] **Step 4.2: 极简认证与登录路由 (`app/api/auth.py`)**
  - **接口**：`POST /api/v1/auth/login`、`GET /api/v1/auth/me`。
- [ ] **Step 4.3: 班级管理业务与路由 (`app/api/classes.py`)**
  - **接口**：教师创建班级（自动生成 6 位邀请码）、学生邀请码加入、查看班级学生名册。
- [ ] **Step 4.4: 作业编排与发布路由 (`app/api/assignments.py`)**
  - **接口**：教师发布作业/考试（练习/考试双模式）、获取作业题目列表、交卷时限控制。
- [ ] **Step 4.5: 判题与自测提交路由 (`app/api/judge.py`)**
  - **接口**：`POST /api/v1/judge/run-test`（自测运行）、`POST /api/v1/judge/submit`（练习提交/考试单次交卷锁定）。
- [ ] **Step 4.6: 专属强化训练题本路由 (`app/api/training.py`)**
  - **接口**：获取个人专属训练题列表、单题详情查看、针对训练题提交判分。
- [ ] **Step 4.7: 教师端班级学情与薄弱点大屏聚合路由 (`app/api/dashboard.py`)**
  - **接口**：`GET /api/v1/assignments/{id}/dashboard`，聚合计算及格率、分数段分布、各题通过率与全班薄弱知识点 Top 统计。
- [ ] **Step 4.8: LLM 业务调度路由 (`app/api/llm.py`)**
  - **接口**：AI 出题、用例生成、考后一键诊断、针对弱点生成强化题、流式问答对话。
- [ ] **Step 4.9: 阶段验收与接口集成测试**
  - **验收测试**：使用 FastAPI 自动生成的 `/docs` Swagger 界面或测试脚本，对全部接口执行自动化全链路测试。
