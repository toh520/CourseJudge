> **重要说明**：本项目所有后续开发（包括 AI 辅助生成代码、人工重构与功能扩展）**必须无条件严格遵守**本文档中定义的开发规范与设计准则。

## 1. 核心工程架构与目录隔离准则

### 1.1 项目根目录划分
- 根目录下仅保留三类核心内容：
  1. `AGENTS.md`：AI Agent 开发行为规范与必须遵守的最高准则。
  2. `docs/`：存放全套系统设计、需求规格、接口与开发规范文档。
  3. `project/`：**所有系统源代码、前端资源、配置文件、测试用例与启动脚本必须统一收敛在 `project/` 文件夹内**，根目录不得散落业务代码。

### 1.2 `project/` 目录分层架构
严格禁止将所有代码堆砌在同一个文件夹下（严禁单文件或扁平化大乱炖）。必须严格遵循清晰的现代分层架构：

## 2. 命名规范与风格准则 (PEP 8 增强)

系统所有文件、类、函数与变量命名必须表意清晰、拒绝无意义的缩写（如 `a`, `b`, `temp1`, `do_stuff`）。

| 元素类型 | 命名规则 | 范例 | 严格禁止反例 |
| :--- | :--- | :--- | :--- |
| **Python 文件名** | 全小写蛇形 (snake_case) | `judge_service.py`, `class_service.py` | `JudgeService.py`, `classService.py` |
| **文件夹 / 模块名** | 全小写蛇形 (snake_case) | `app`, `core`, `services`, `temp_judge` | `AppCore`, `Services_V1` |
| **Python 类名** | 大驼峰式 (PascalCase) | `JudgeService`, `CompilerProbe`, `User` | `judge_service`, `user_model` |
| **函数与方法名** | 全小写蛇形 (snake_case) | `compile_and_run()`, `get_assignment_dashboard()` | `CompileAndRun()`, `getAssignmentDashboard()` |
| **局部与类成员变量**| 全小写蛇形 (snake_case) | `execution_time_ms`, `invite_code`, `passed_cases`| `executionTimeMs`, `InviteCode` |
| **全局常量 / 配置** | 全大写蛇形 (SCREAMING_SNAKE) | `DEFAULT_TIMEOUT_SECONDS`, `DATABASE_URL` | `defaultTimeout`, `databaseUrl` |
| **数据库表名与字段**| 全小写蛇形 (snake_case) | 表: `class_members`, 字段: `created_at` | 表: `ClassMembers`, 字段: `createdAt` |

## 3. 标准中文注释规范

根据项目核心要求，**在所有关键逻辑、复杂算法、模型定义及类/函数声明处，必须书写规范的标准中文注释**：

### 3.1 模块与类说明
每个 Python 文件顶部与主要类声明前必须包含中文 Docstring，阐明该模块/类的职责：
```python
"""
文件名: judge_service.py
功能描述: 提供 C++ 源代码的受限编译、测试用例遍历评测、超时强杀以及结果比对服务。
"""

class JudgeService:
    """
    C++ 代码评测调度器类
    负责协调编译器探针定位 g++ 路径，并在独立沙箱中安全执行学生代码。
    """
```

### 3.2 函数与方法标准注释
必须清晰说明：**功能、输入参数、返回值及可能抛出的异常**：
```python
def execute_test_case(executable_path: str, input_data: str, timeout_seconds: float = 1.0) -> dict:
    """
    在受限子进程中执行 C++ 可执行程序并喂入测试输入

    参数:
        executable_path (str): 编译生成的可执行二进制文件绝对路径
        input_data (str): 喂入标准输入 (stdin) 的测试用例数据文本
        timeout_seconds (float): 单点最大执行时间阈值 (默认 1.0 秒)

    返回:
        dict: 包含执行状态、标准输出、耗时毫秒数以及错误信息的结果字典
              {
                  "status": "Accepted" | "Time Limit Exceeded" | "Runtime Error",
                  "stdout": str,
                  "time_ms": int,
                  "error_msg": str
              }
    """
```

### 3.3 关键步骤行内注释
在涉及边界条件、算法跳转、并发控制或复杂逻辑处，必须附带说明为什么这么做，例如：
```python
# 清理输出文本末尾的换行符与多余空白，避免由于 Windows/Linux 换行符差异导致判题错误
normalized_output = stdout_text.rstrip()
normalized_expected = expected_text.rstrip()
```

## 4. 全局数据库设计精简准则 (克制实用原则)

为了降低课设开发难度、提高运行效率并让答辩演示更加直观，系统**所有数据表的设计必须遵循极致的克制与精简原则**：
1. **全系统拒绝冗余字段（以用户表为典范）**：
   - 严禁添加非业务核心字段。例如用户注册时，手机号、邮箱、头像、微信号等与课设无关的字段**一概不加**；仅保留完成教学闭环所必需的最少字段：
     `id`, `username` (学号/工号), `real_name` (姓名), `password` (密码), `role` (角色: teacher/student), `created_at`。
   - **此原则适用于全系统所有表**（班级表、作业表、题目表、用例表、提交表、强化题表等），每张表每一列都必须有明确的业务支撑，严禁过度设计。
2. **密码免加密（明文存储）**：
   - 为方便课设阶段直观调试、测试账号快速登录以及老师直接查验数据库数据，**系统密码直接以明文字符串形式存储**，不做加盐哈希，免去复杂的 bcrypt/passlib 加密流程。

## 5. 环境配置全局外部化与防泄露准则 (零硬编码原则)

### 5.1 全局零硬编码原则
**绝对禁止将任何可能变动的环境参数硬编码在 Python 代码中！**
不仅是密钥，以下所有系统运行配置都必须抽离至外部配置文件：
1. **大模型 (LLM) 配置**：
   - `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL_NAME`。
   - 必须通过标准的 **OpenAI 兼容协议客户端 SDK** (`openai.OpenAI(base_url=..., api_key=...)`) 进行调用，确保无论切换到哪家大模型平台，代码层完全零修改。
2. **数据库连接配置**：
   - `DATABASE_URL`（无论是本地 `sqlite:///./course_judge.db` 还是后续切 MySQL，必须从配置文件读取）。
3. **系统运行参数**：
   - 服务端口号、超时阈值（`DEFAULT_TIME_LIMIT_MS`）、编译器探针工作模式等。

### 5.2 配置文件双轨机制与 Git 绝密防线
1. **`.env.example` (受版本控制追踪)**：
   - 作为配置模板提交至 Git 仓库，里面**绝对不填写真实密钥**，仅提供占位符与中文使用注释。
2. **`.env` (被 `.gitignore` 严格忽略)**：
   - 本地实际运行环境所需的真实私密配置，由开发者本地复制生成，严禁上传。
3. **本地敏感数据源保护**：
   - 本地记录真实密钥的任何临时文档（如 `llm.txt` 等）已被根目录和子目录的 `.gitignore` 严格忽略，**严禁将真实 Key 写入设计文档或提交到代码仓库中**。

## 7. 团队协同开发与“一键启动脚本”持续同步维护

由于本项目为多人团队协作开发，为了杜绝“一人开发、全队报错”的环境不一致问题，系统提供全自动初始化的启动脚本并要求持续维护：

### 7.1 启动脚本架构
1. **根目录入口 [`一键启动.bat`](file:///d:/code/school/keshe/CourseJudge/%E4%B8%80%E9%94%AE%E5%90%AF%E5%8A%A8.bat)**：
   面向所有团队成员与评审老师的顶层双击快捷入口，利用 `%~dp0` 安全相对路径无缝转入 `project/` 并触发主脚本。
2. **主脚本 [`project/start.bat`](file:///d:/code/school/keshe/CourseJudge/project/start.bat)**：
   - 自动检测 Python 3.10+ 运行环境；
   - 自动检测并一键创建 `.venv` 虚拟环境；
   - 自动调用清华大学高速镜像源（`https://pypi.tuna.tsinghua.edu.cn/simple`）静默同步并校验 `requirements.txt`；
   - 自动检测 `.env`，若首次运行无此文件，自动从 `.env.example` 复制初始化，并在终端友善提示；
   - 自动确保本地临时工作路径（如 `storage/temp_judge/` 等）存在；
   - 调用虚拟环境解释器一键拉起 `run.py` 桌面应用。

### 7.2 持续同步与 Skill 维护机制
- 项目在 [`.agents/skills/maintain-startup-scripts/SKILL.md`](file:///d:/code/school/keshe/CourseJudge/.agents/skills/maintain-startup-scripts/SKILL.md) 中封装了专属维护技能；
- 每次在代码中增删第三方库、变更环境变量或调整服务启动入口时，AI Agent **必须调用该 Skill**，同步更新 `requirements.txt`、`.env.example` 并测试 `start.bat` 的可用性。

## 8. AI 协作开发时的强制守则

后续由 AI 代理进行各模块代码编写时，必须执行如下自检：
1. **位置检查**：生成的新文件路径必须在 `project/` 目录下，严禁在根目录下散落非规范文件；
2. **分层检查**：路由函数不得直接操作数据库底层 SQL，必须通过 Service 层流转；
3. **注释检查**：编写的每一个类与函数，必须带有标准的中文 Docstring 说明；
4. **外部化检查**：所有数据库连接、LLM API Key 与模型地址必须从 `project/app/core/config.py` 中读取；
5. **极简检查**：新增数据表时严格杜绝冗余字段，密码保持明文存储；
6. **启动脚本同步**：凡涉及新增依赖或环境变量改动，必须调用 `maintain-startup-scripts` 技能同步维护 `start.bat`。
