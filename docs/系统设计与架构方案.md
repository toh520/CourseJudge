# 智能代码判题与教学辅助系统 (CourseJudge) - 系统设计与架构方案

## 1. 最终技术栈选型规范

为了兼顾“**桌面软件独立窗口运行体验**”、“**现代化的 VS Code 级代码编辑器与大屏可视化**”以及“**免装 C++ 环境、开箱即用、随拷随走**”的设计目标，系统敲定以下技术组合：

| 维度 | 选型技术 | 核心优势与决策依据 |
| :--- | :--- | :--- |
| **客户端形态** | **PyWebView (独立桌面窗口)** | 以纯 Python 驱动，启动时自动唤起原生 Windows 独立窗口，拥有传统桌面软件的双击即用体验，无需用户在外部浏览器手动输入 URL。 |
| **后端业务核心** | **Python (FastAPI + Uvicorn)** | 高性能异步非阻塞框架，处理并发编译判题天然高效；原生支持 SSE (Server-Sent Events) 流式大模型打字机输出；内嵌随应用一同启动。 |
| **持久层数据库** | **SQLite 3 + SQLAlchemy 2.0 ORM** | **项目级单文件数据库**（`course_judge.db`），零安装、免配置环境，拷贝到任何新电脑数据完好无损。通过 ORM 抽象底层方言，后续若需升级为局域网/互联网 MySQL 共享库，仅需修改一行连接配置，业务代码零改动。 |
| **C++ 评测引擎** | **Python 子进程 + 智能双模探针** | 采用**智能双模自适应探针 (Smart Compiler Probe)**。优先检测系统 `g++`；若未安装，平滑降级使用项目内置精简便携版（约 40~50MB），做到**真正的“零环境依赖，落地即用”**。 |
| **前端交互组件** | **Monaco Editor + ECharts 5** | 代码编辑器采用微软官方 VS Code 核心（Monaco），具备出色的 C++ 语法高亮、缩进与行号；学情大屏采用 ECharts 渲染动态直方图、漏斗图与雷达图。 |
| **大语言模型 API** | **OpenAI SDK / HTTP 客户端** | 采用通用标准 OpenAI API 格式接入（推荐 DeepSeek-V3/R1、阿里通义千问等），配置灵活，支持一键切换模型。 |

## 3. 核心机制详细设计

### 3.1 编译器“智能双模自适应探针”详细设计

#### 3.1.1 为什么需要双模探针？
- **传统方式的弊端**：要么强求目标电脑配置环境变量（非计算机专业电脑直接报错闪退），要么每次都打包几十 G 的大型工具。
- **双模探针的工作逻辑**：
  ```mermaid
  flowchart TD
      Start[判题任务到达] --> CheckEnv{执行 where g++ 检查系统 PATH}
      CheckEnv -->|系统已配置 MinGW| UseSystem[使用本机 g++ 编译器: 0 MB 开销]
      CheckEnv -->|系统未安装| CheckLocal{检查项目内 ./compiler/bin/g++.exe 是否存在}
      CheckLocal -->|存在内置绿色编译器| UseLocal[使用项目内置便携编译器: 零配置开箱即用]
      CheckLocal -->|均不存在| ThrowError[弹出友好诊断弹窗: 提示配置路径或放入便携编译器]
      UseSystem --> CompileRun[调用 subprocess 编译及执行]
      UseLocal --> CompileRun
  ```

#### 3.1.2 内置绿色便携编译器规划
- 在项目根目录下预留 `compiler/` 目录结构：
  ```text
  CourseJudge/
  └── compiler/
      └── bin/
          ├── g++.exe
          ├── as.exe
          ├── ld.exe
          └── ... (精简核心动态链接库)
  ```
- 基于开源成熟的 `w64devkit` 进行裁剪，剔除不必要的 `gdb`、文档、`make` 工具，仅保留 C++ 核心编译链，**解压后体积控制在约 40~50MB**。
- **课设分发优势**：将整个项目打包为 `.zip` 或利用 PyInstaller 打包时，目标电脑哪怕是纯净的新机，也能双击即跑，完全免去环境配置。

### 3.2 数据库可移植性与无缝共享升级设计 (SQLAlchemy 2.0)

数据源配置采用抽象解耦设计，保存在 `app/core/config.py`：

```python
# 默认采用本地 SQLite 文件，演示时随拷随走，无需任何外部数据库服务
DATABASE_URL = "sqlite:///./course_judge.db"

# 若后续需求变更为多人网络协同或联网部署，仅需取消注释并填写 MySQL/PostgreSQL 连接即可：
# DATABASE_URL = "mysql+pymysql://root:password@192.168.1.100:3306/course_judge?charset=utf8mb4"
```
所有业务逻辑均通过统一的 ORM 模型交互，底层 SQL 差异被完全抹平。

### 3.3 数据模型全量设计 (精简克制原则)

数据库实体遵循极致克制原则，剔除邮箱、电话等与课设答辩无关的字段。

#### 1. 用户表 (`users`) - 极简结构
- `id` (INTEGER, PK): 主键
- `username` (VARCHAR(50), UNIQUE): 登录名 / 学号 / 工号
- `password` (VARCHAR(50)): **登录密码 (明文存储，方便课设直观调试)**
- `real_name` (VARCHAR(50)): 真实姓名
- `role` (VARCHAR(20)): 身份 (`teacher` 教师, `student` 学生)
- `created_at` (DATETIME): 创建时间

#### 2. 班级表 (`classes`)
- `id` (INTEGER, PK): 主键
- `name` (VARCHAR(100)): 班级名称
- `invite_code` (VARCHAR(10), UNIQUE): 6 位随机邀请码
- `teacher_id` (INTEGER, FK $\to$ users.id): 创建教师
- `created_at` (DATETIME): 创建时间

#### 3. 班级成员表 (`class_members`)
- `id` (INTEGER, PK): 主键
- `class_id` (INTEGER, FK $\to$ classes.id): 班级ID
- `student_id` (INTEGER, FK $\to$ users.id): 学生用户ID
- `joined_at` (DATETIME): 加入时间

#### 4. 作业/考试活动表 (`assignments`)
- `id` (INTEGER, PK): 主键
- `class_id` (INTEGER, FK $\to$ classes.id): 所属班级ID
- `title` (VARCHAR(100)): 活动标题
- `type` (VARCHAR(20)): 模式 (`practice` 练习模式, `exam` 考试模式)
- `start_time` (DATETIME): 开始时间
- `end_time` (DATETIME): 截止时间
- `created_by` (INTEGER, FK $\to$ users.id): 发布教师ID

#### 5. 题目表 (`problems`)
- `id` (INTEGER, PK): 主键
- `assignment_id` (INTEGER, Nullable, FK $\to$ assignments.id): 所属作业（题目直接归属于作业）
- `title` (VARCHAR(100)): 题目标题
- `description` (TEXT): 题目描述（Markdown格式）
- `input_format` (TEXT): 输入格式说明
- `output_format` (TEXT): 输出格式说明
- `sample_input` (TEXT): 公开输入样例
- `sample_output` (TEXT): 公开输出样例
- `time_limit_ms` (INTEGER): 时间限制（毫秒，默认 1000）
- `memory_limit_mb` (INTEGER): 空间限制（MB，默认 256）
- `knowledge_tag` (VARCHAR(50)): 核心知识点（如“动态规划”、“二叉树遍历”）
- `is_ai_generated` (BOOLEAN): 是否为 AI 辅助生成

#### 6. 测试用例表 (`test_cases`)
- `id` (INTEGER, PK): 主键
- `problem_id` (INTEGER, FK $\to$ problems.id): 关联题目
- `input_data` (TEXT): 评测输入数据
- `output_data` (TEXT): 标准期望输出数据
- `score_weight` (INTEGER): 分值占比

#### 7. 提交记录表 (`submissions`)
- `id` (INTEGER, PK): 主键
- `user_id` (INTEGER, FK $\to$ users.id): 提交学生ID
- `problem_id` (INTEGER, FK $\to$ problems.id): 题目ID
- `assignment_id` (INTEGER, FK $\to$ assignments.id): 所属作业
- `code` (TEXT): 提交的 C++ 源码
- `status` (VARCHAR(30)): 评测状态 (`AC`, `WA`, `TLE`, `RE`, `CE`)
- `score` (INTEGER): 最终得分 (0~100)
- `time_used_ms` (INTEGER): 运行耗时
- `compiler_output` (TEXT): 编译失败日志
- `is_final` (BOOLEAN): 是否为考试最终交卷记录
- `created_at` (DATETIME): 提交时间

#### 8. 学生专属强化训练题表 (`training_problems`)
- `id` (INTEGER, PK): 主键
- `student_id` (INTEGER, FK $\to$ users.id): 归属学生ID
- `source_assignment_id` (INTEGER, FK $\to$ assignments.id): 来源作业诊断ID
- `knowledge_tag` (VARCHAR(50)): 针对巩固的薄弱知识点标签
- `title` (VARCHAR(100)): 题目名称
- `description` (TEXT): 题面 Markdown
- `sample_input` (TEXT): 样例输入
- `sample_output` (TEXT): 样例输出
- `test_cases_json` (TEXT): 自动配套的评测用例集 (JSON)
- `best_status` (VARCHAR(20)): 学生历史最佳状态 (`Unsolved`/`AC`/`WA`)
- `created_at` (DATETIME): 生成时间

#### 9. AI 助手问答历史表 (`chat_messages`)
- `id` (INTEGER, PK): 主键
- `user_id` (INTEGER, FK $\to$ users.id): 用户ID
- `role` (VARCHAR(20)): 消息角色 (`user`, `assistant`)
- `content` (TEXT): 对话文本内容
- `created_at` (DATETIME): 时间戳

## 4. 教师端班级学情与薄弱点大屏设计

大屏作为教师端核心教学辅助模块，提供直观的数字化看板：
1. **班级作业宏观画像**：
   - 应交总人数、已交卷人数、批改完成率。
   - 分数段分布直方图（$90\sim 100$ 优秀、$80\sim 89$ 良好、$60\sim 79$ 及格、$<60$ 待加强）。
2. **题目答题漏斗与失分类型占比**：
   - 每道题的 AC 通过率折线图。
   - 错误类型饼图（区分是算法超时 TLE，还是逻辑错误 WA，或是语法未过 CE）。
3. **班级薄弱知识点 Top 诊断**：
   - 聚合计算班级失分最多的知识点 Top 3，直观呈现（例如：“全班 64% 学生在【动态规划-状态转移方程】上丢分”），并在大屏下方为老师生成一键讲评建议。
